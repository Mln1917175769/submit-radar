## 一、项目背景

班级作业要求每人提交一个 GitHub 仓库，由助教人工逐个点开核对：仓库在不在、是不是私有、有没有 README、命名规不规范。人数一多，这件事既慢又容易漏。

本项目把这段人工重复劳动自动化：**输入是一段群聊记录，输出是一张逐人的检查总览表**，并针对不同问题自动生成对应的催办话术。

---

## 二、功能特性

- 用正则解析群聊文本，自动提取 GitHub 仓库链接与 @ 人名
- 调用 GitHub 接口核对仓库：是否存在、是否私有、是否有 README
- 按规则对项目命名打分，命中随意命名自动扣分
- 按不同问题类型生成对应催办话术，可直接发群
- 错误分类提示：链接格式错误、仓库不存在、请求限流、证书错误、超时分别给出不同提示

---

## 三、技术栈

- 语言：Python 3.8 及以上
- 界面：Streamlit
- 网络请求：requests
- 数据来源：GitHub REST API
- 文本解析：正则表达式

---

## 四、快速开始

### 1. 安装依赖

    pip install streamlit requests

### 2. 配置访问令牌（可选但推荐）

到 GitHub 个人设置中生成一个访问令牌，填入界面上的输入框。

不填也能使用，但未认证请求每小时只有 60 次额度，人多时会很快超限。

### 3. 运行

    streamlit run app.py

### 4. 使用

在浏览器打开的页面中粘贴群聊记录，点击「开始检查」，等待结果表格生成。

---

## 五、工作原理

整体流程分为三段：

1. **解析**：用正则从群聊文本中提取「人名 + 仓库链接」
2. **核对**：逐个调用 GitHub 接口，判断仓库是否存在、是否私有、有无 README，并按规则打分
3. **呈现**：按规则汇总成表格，并按问题类型生成催办话术

## 七、常见问题

**问：检查时报 SSL 证书错误怎么办？**

答：这通常是 Python 请求没有走代理、而浏览器走了代理导致的，两者网络路径不一致。可以尝试两种方式：

- 给 Python 配置代理环境变量，指向本机的代理端口
- 排查杀毒软件对本机 HTTPS 流量的拦截

**问：为什么有的仓库查不到？**

答：GitHub 对未认证请求，会把「私有仓库」和「不存在」都返回 404，两者无法区分。填入有权限的令牌后，才能分辨究竟是私有还是真的不存在。

**问：提示请求次数超限怎么办？**

答：未认证请求每小时只有 60 次额度。填入访问令牌后，额度可提高到每小时 5000 次。

**问：为什么要填访问令牌？**

答：一是提高请求额度，避免限流；二是对于私有仓库，只有携带有效令牌才能查询到。

## 八、已知限制

- 使用代理的环境下，Python 请求可能报证书错误，需要额外配置
- 群昵称与 GitHub 账号无法自动对应，人名仅用于生成催办话术
- 只支持 GitHub 链接，暂不支持其他代码托管平台
- 请求为串行执行，仓库数量较多时等待时间较长
- 尚未编写单元测试
